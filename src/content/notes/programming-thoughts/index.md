这个专题不是“背 23 个设计模式”。它把原课程的 46 个分 P 重构成一条可实践的路线：先看见坏味道，再找到变化轴，最后用最小的抽象保护稳定部分。

## 建议阅读顺序

1. [进入 46 讲完整课程](/notes/programming-thoughts/course)：每个 B 站分 P 对应一篇独立精讲。
2. 先完成 P1–P16 的设计原则，再进入具体模式；没有原则作判断，模式只会变成类图模板。
3. 每一讲都先运行“坏设计”，再做重构，最后回答“什么时候不该使用”。
4. 读完一个阶段，回到自己的项目寻找一个真实变化点，不要凭空创造抽象。

## 全系列统一思考框架

```text
坏味道是什么？
→ 哪一类需求反复变化？
→ 哪些代码必须保持稳定？
→ 协作边界应放在哪里？
→ 新结构付出了什么代价？
```

模式名称只负责交流。真正能迁移到新项目里的，是这五个问题。

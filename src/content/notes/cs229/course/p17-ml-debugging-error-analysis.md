## 诊断优先

模型效果不好时，可做的事情很多：

- 增加数据；
- 增加特征；
- 换更复杂模型；
- 加正则化；
- 训练更久；
- 修改指标；
- 清理标签。

这些动作解决的问题不同。没有诊断就并行尝试，成本高且难以归因。

## 建立可靠基线

第一个系统应尽快跑通：

```text
数据读取
→ 训练
→ 验证
→ 指标
→ 错误样本
```

基线可以简单，但必须可复现、没有泄漏，并能导出逐样本预测。

没有逐样本结果，就无法做真正的误差分析。

## 人类水平与 Bayes 误差

训练误差、验证误差需要相对于不可约误差解释。

如果人类专家错误率为 $1\%$，训练错误 $10\%$，可能存在较大可避免偏差。

若任务本身标签含糊，人类也只能达到 $12\%$，训练错误 $13\%$ 未必说明严重欠拟合。

人类水平只是 Bayes 误差的代理，并非所有任务都适用。

## 偏差诊断

高偏差常表现为：

- 训练误差明显高于可达到基准；
- 增加训练数据帮助有限；
- 训练和验证误差都高且接近。

可能措施：

- 更强表示；
- 更有信息的特征；
- 减弱正则化；
- 优化更充分；
- 修正错误目标或标签。

## 方差诊断

高方差常表现为：

- 训练误差低；
- 验证误差明显更高；
- 增加数据常有帮助；
- 不同随机划分结果波动大。

可能措施：

- 增加数据或数据增强；
- 加强正则化；
- 减小模型；
- 改善划分；
- 集成多个模型；
- 清理泄漏和重复样本。

## 学习曲线

使用不同训练集规模 $m$，绘制训练与验证误差。

高偏差时，两条曲线在较高误差处接近；继续加数据改善有限。

高方差时，训练误差低、验证误差高，差距可能随数据增加缩小。

每个数据规模应重新训练，不是只截取同一次训练过程的前几步。

## 优化误差与统计误差

训练损失没有接近当前模型可达到水平，属于优化问题。

训练目标已经很低、验证差，更多是统计或泛化问题。

比较优化器前先固定模型、数据和目标。换模型后损失刻度可能变化，不能直接比较数值。

## 目标函数与评估指标

优化代理损失：

$$
J_{\mathrm{train}}
$$

最终关心：

$$
M_{\mathrm{business}}
$$

如果训练损失持续下降而业务指标不改善，可能是：

- 代理目标不匹配；
- 类别权重不合理；
- 阈值未调整；
- 概率未校准；
- 评估切片与部署分布不同。

不要把“优化器没做好”与“优化了错误目标”混为一谈。

## 手工误差分析

从验证集错误中随机抽样，建立互斥或可重叠的错误类别：

- 标签错误；
- 输入质量问题；
- 长尾类别；
- 歧义样本；
- 缺少上下文；
- 阈值问题；
- 分布外样本。

统计每类占比和可修复程度。

如果某问题只占全部错误的 $1\%$，即使完全解决，对总体指标提升也有限。

## Ceiling Analysis

对流水线模块依次提供“完美输出”，观察整体指标提升上限。

例如：

```text
检测 → 识别 → 排序 → 决策
```

若把检测结果替换为人工真值后整体只提升 $0.2\%$，就不应优先投入检测模块。

这比孤立比较模块准确率更接近系统价值。

## 消融实验

从完整系统移除一个组件，观察性能变化：

$$
\Delta_j
=M_{\mathrm{full}}
-M_{\mathrm{without}\ j}
$$

消融能回答组件是否真的贡献，但组件存在交互，单独贡献不能简单相加。

实验要保持训练预算、随机种子、数据和调参机会公平。

## 数据质量诊断

按来源和时间查看：

- 缺失率；
- 标签分布；
- 重复样本；
- 特征范围；
- 训练/验证分布差异；
- 标签延迟；
- 采样机制。

性能问题经常来自数据 pipeline，而不是算法。

## 强化学习系统诊断

RL 总回报差可能来自：

- 奖励函数错误；
- 环境或模拟器错误；
- 探索不足；
- 价值估计错误；
- 优化不稳定；
- 评估随机性过大。

应先用已知策略、人工轨迹和小环境分别验证奖励、转移和价值计算，再训练完整 agent。

## 实验记录

每次实验记录：

- 明确假设；
- 唯一主要变量；
- 数据与代码版本；
- 随机种子；
- 训练预算；
- 总体和切片指标；
- 结论与下一步。

没有实验记录，团队会重复无效尝试，也难以判断改进来自代码还是随机波动。

## 一套从现象到行动的诊断树

先确认评价管道可信：

```text
指标实现正确吗？
数据划分符合部署方式吗？
是否存在标签或特征泄漏？
基线分数是否合理？
```

若基础管道可信，再比较训练误差与可达到误差。

训练误差很高：

```text
能否过拟合小批量？
优化是否收敛？
特征与标签是否对齐？
模型容量是否不足？
```

训练误差低、验证误差高：

```text
训练/验证分布是否一致？
数据量是否不足？
正则和模型容量是否合适？
是否存在重复实体或泄漏？
```

训练和验证都好、线上差：

```text
线上特征处理是否一致？
分布是否漂移？
延迟或资源约束是否改变模型？
反馈与标签是否延迟或偏置？
```

每次实验只针对一个明确假设。否则即使分数变化，也不知道是哪项修改造成。

## 学习曲线的定量读法

用不同训练集大小 $m$ 训练模型，记录训练和验证误差。

高偏差常表现为：训练误差和验证误差都高，且两者接近。增加更多同分布数据通常帮助有限，应改进表示、特征或优化。

高方差常表现为：训练误差低、验证误差明显高。更多数据、正则化、数据增强和减小模型容量可能有效。

若两条曲线仍随数据量持续下降，继续收集数据可能值得。

学习曲线必须在相同验证集和训练协议下比较。小训练子集仍要保持类别与群组结构，不能随意抽样破坏任务分布。

## 手工误差分析表

抽取一批验证错误，为每个样本标注互不排斥的失败标签：

| 维度       | 示例                     |
| ---------- | ------------------------ |
| 标签问题   | 标注错误、定义含糊       |
| 输入质量   | 模糊、缺失、截断         |
| 未覆盖模式 | 新术语、新设备、新地区   |
| 模型能力   | 长程依赖、非线性关系     |
| 阈值问题   | 分数合理但决策阈值不合适 |
| 分布变化   | 验证中稀少、线上常见     |

统计每类错误占比和修复上限。若 60% 错误来自标签含糊，继续扩大模型可能不是首要动作。

抽样时既看随机错误，也看高置信错误。高置信错误常暴露泄漏、系统性偏差或错误标签。

## Ceiling Analysis

系统由多个模块组成：

```text
输入解析
→ 候选生成
→ 特征提取
→ 分类
→ 后处理
```

依次把某个模块替换为人工真值，观察最终指标最大能提升多少。

如果把候选生成替换为真值只提升 0.2%，就不应优先重写该模块。

如果完美输入解析能提升 15%，说明上游数据或解析是高价值瓶颈。

Ceiling Analysis 衡量的是修好模块的潜在上限，不是预计实际收益，但能避免团队把时间投入低上限环节。

## 消融实验与对照实验

消融实验移除一个组件：

$$
\Delta_j
=
\operatorname{metric}(\text{full})
-
\operatorname{metric}(\text{without }j)
$$

若移除后指标几乎不变，组件可能无效、冗余，或被其他模块替代。

对照实验要保持数据、种子、训练预算和评价协议一致。最好运行多个种子并报告均值与波动。

不能把“新模型训练更久”与“旧模型训练较短”直接归因于架构改进。资源预算也是实验变量。

## 数据问题的优先级

先检查标签定义是否一致。同一输入若不同标注者系统性分歧，模型上限会受标签噪声限制。

再检查训练与验证重复。近重复样本跨集合会让验证分数虚高。

检查缺失值模式。缺失本身可能泄漏业务流程，也可能在线上发生改变。

检查特征时间戳。预测时刻之后生成的字段必须删除。

检查切片覆盖。总体样本很多不代表关键少数场景有足够数据。

数据修复应版本化，并重新跑全部基线，不能只在新模型上测试。

## 一个完整调试案例

假设文本分类器训练 Accuracy 为 $99\%$，验证 Accuracy 为 $84\%$。

第一步，检查随机标签基线和多数类基线，确认指标代码正常。

第二步，按文档来源分组，发现同一来源的模板文本在训练集大量重复，而验证集含新来源。

第三步，按来源重新划分，训练分数仍高，验证分数降到 $72\%$。旧分数存在实体泄漏。

第四步，手工分析 200 个错误，发现 45% 来自新术语、30% 来自截断文本、15% 是标签不一致。

第五步，分别实验：扩充术语数据、增加输入长度、清理标签。每项单独对照。

最终即使只提升到 $80\%$，这个分数也比原来的 $84\%$ 更可信，因为它模拟真实部署并解释了主要误差来源。

## 实验记录模板

每次实验记录：

```text
问题：
证据：
假设：
唯一改动：
预期结果：
训练预算：
主指标与约束：
切片结果：
结论：
下一步：
```

“换了更大的模型，分数提高”不是完整记录。还要说明数据版本、随机种子、对照、成本和波动。

失败实验同样重要。它能关闭一条假设路径，避免团队重复尝试。

## 练习与答案思路

### 练习 1：高偏差

训练和验证误差都高且接近，应优先增加正则还是提升模型表达能力？

答案思路：优先检查优化后提升表达能力或特征；继续增加正则通常会让偏差更高。

### 练习 2：高方差

训练误差极低、验证误差高，增加同分布数据可能有帮助吗？

答案：通常有帮助，也可增强正则、数据增强或简化模型。

### 练习 3：线上退化

离线测试稳定，线上突然变差，第一批证据应从哪里收集？

答案思路：检查线上输入/特征协议、数据漂移、服务降级、阈值和反馈延迟，而不是直接重训。

### 练习 4：错误占比

误差分析发现 70% 错误来自图片过暗，应优先优化分类器最后一层吗？

答案：不应。先改善采集、图像增强或专门覆盖低照度数据。

## Sanity Check 清单

训练前：

```text
随机抽样可视化
标签与输入对齐
类别和数值范围
训练/验证无重复
简单基线
随机标签测试
```

训练中：

```text
loss 初值合理
参数确实更新
梯度有限
小数据可过拟合
验证没有进入反向传播
```

训练后：

```text
高置信错例
切片指标
预测分布
与基线配对差异
线上预处理一致
```

Sanity Check 成本低，却能消灭大量“调了几天超参数才发现标签反了”的问题。

## 随机标签与随机特征测试

把训练标签随机打乱。

高容量模型可能仍能拟合训练集，但验证指标应接近随机。

如果验证仍然很好，几乎肯定存在泄漏、重复或指标错误。

把关键特征随机打乱，性能应下降。若不下降，模型可能没使用该特征，或存在替代变量。

只保留一个可疑特征训练，若表现异常高，检查它是否直接编码标签或预测后信息。

## 数据集重复与污染

精确重复可用 hash 检查。

近重复需要图像感知 hash、文本 MinHash/Embedding 或实体规则。

同一模板只改少量字段，随机划分可能让模型记忆模板。

外部预训练模型可能已经见过测试 benchmark，称为训练数据污染。评价时应记录预训练来源并使用新鲜或私有 holdout。

去重规则必须在数据版本中保存。

## Slice Discovery

预定义关键切片基于领域风险。

还可以探索模型在哪些区域系统性失败：

- 按损失排序；
- 聚类错误样本；
- 用简单树预测“模型是否出错”；
- 按输入质量和置信度分箱。

探索切片上的发现需要在独立数据复核，否则会过拟合切片搜索。

不能无限切分到只剩几个样本，然后把偶然差异当作规律。

## Counterfactual 与扰动测试

对输入做保持标签语义的小变化：

```text
图片亮度
文本同义替换
表格数值小扰动
无关字段变化
```

预测应在合理范围内稳定。

若改变姓名格式就大幅改变风险，模型可能依赖代理敏感特征或数据伪相关。

Counterfactual 不是因果证明，但能发现不应敏感的输入依赖。

## 训练服务一致性

离线和线上必须共享：

- 特征定义；
- 缺失处理；
- 类别词表；
- 标准化参数；
- 时间窗口；
- 模型版本；
- 阈值。

可以对同一批原始请求同时运行离线和服务代码，比较最终特征与 logits。

设置 Golden Examples，部署前后输出必须在容差内一致。

## 漂移监控

输入漂移可用 PSI、KL/JS、Wasserstein、KS 等统计，但阈值要结合样本量和业务意义。

Prediction Drift 检查分数和类别比例变化。

Concept Drift 需要延迟标签后检查性能与校准。

监控切片应对应高风险群体，不只看总体平均。

报警后要有诊断和回滚流程。只有 dashboard 没有责任人，不构成可运行监控。

## 误差预算

把系统错误分配到组件：

```text
数据/标签
召回
模型排序
阈值
后处理
服务失败
```

设总体错误 1000 个，若召回阶段已经漏掉 600 个，优化排序模型最多修复剩余部分。

结合 Ceiling Analysis 估计每层可减少多少错误与实现成本，形成优先级。

## 调试项目

人为给一个基线系统注入至少四类 bug：

```text
标签错位
验证泄漏
学习率过大
线上标准化不一致
```

只根据日志、曲线、切片和小实验定位，不先查看答案。

为每个 bug 写：

```text
症状
排除证据
根因
最小修复
回归测试
```

最终沉淀自动检查，让同类错误不能再次静默发生。

## 补充练习

### 练习 5：随机标签

随机标签后验证 AUC 仍为 0.95，最可能说明什么？

答案：数据泄漏、训练/验证重复或评价实现错误。

### 练习 6：近重复

为什么只删除完全相同文件可能不够？

答案：裁剪、压缩、模板改写等近重复仍可跨 split 泄漏。

### 练习 7：漂移

输入分布不变是否保证模型性能不变？

答案：不保证，$p(y\mid x)$ 可能发生 Concept Drift。

## 生产事故案例：模型没有变，系统为什么变差

某信用风险模型连续运行半年，某天批准率明显下降。

模型文件 SHA、服务版本和阈值都未改变。

第一反应不能是“重新训练”。先画系统链路：

```text
原始申请
→ 数据接入
→ 特征服务
→ 模型
→ 阈值
→ 规则后处理
→ 最终决策
```

逐层比较事故前后。

### 输入层

发现第三方收入字段缺失率从 2% 升到 35%。

缺失值被填成零，模型把它解释为低收入，而不是“数据源失败”。

### 特征层

线上特征统计与离线训练不同：

$$
P_{\text{online}}(x_{\text{income}}=0)
\gg
P_{\text{train}}(x_{\text{income}}=0)
$$

这是数据质量与语义漂移，不是模型参数漂移。

### 模型层

使用事故前保存请求离线重放，离线和线上 logits 一致，说明推理实现没有分叉。

### 决策层

阈值和规则未改变，但分数整体下移，导致批准率下降。

### 修复

短期回滚到不依赖该字段的备用模型。

中期把缺失指示加入特征，并让特征服务区分：

```text
真实值 0
未知
第三方服务异常
```

长期给关键特征设置 freshness、缺失率和分布报警。

### 回归测试

模拟第三方字段全缺失，系统必须：

- 触发报警；
- 切换回退路径；
- 不把缺失解释为真实零；
- 保持决策率在安全范围。

这个案例说明“模型调试”经常是系统调试。

## 错误分析的统计抽样

只看最严重错误会高估极端问题，只看随机错误又可能错过高风险尾部。

建议三组样本：

1. 随机错误样本，估计错误类型总体比例；
2. 高置信错误，发现系统性与标签问题；
3. 高业务成本错误，聚焦安全与价值。

每组独立统计，不把定向抽样比例当总体比例。

若两位分析者标注错误类型，计算一致性并讨论定义分歧。

建立层级标签：

```text
数据
  ├─ 标签错误
  ├─ 输入缺失
  └─ 分布未覆盖
模型
  ├─ 表达不足
  ├─ 优化失败
  └─ 校准/阈值
系统
  ├─ 特征不一致
  ├─ 服务降级
  └─ 反馈循环
```

## 假设驱动实验的反例

坏实验：

```text
换更大模型
加新特征
调学习率
改数据增强
训练更久
```

结果提升 1%，但无法归因。

好实验：

```text
证据：低照度切片 Recall 比总体低 20%
假设：训练集缺少低照度样本
唯一改动：加入真实低照度训练数据
固定：模型、优化、训练预算
预期：低照度 Recall 提升，总体不显著下降
```

结果无提升也有价值：关闭“覆盖不足”假设，继续检查传感器噪声或表示能力。

## 调试顺序的成本意识

优先做高信息、低成本检查：

```text
数据可视化
shape/assert
小批量过拟合
基线
重放一致性
错误抽样
```

之后再做：

```text
大规模重训
新架构
新数据采集
系统重写
```

调试的目标是最大化单位实验成本获得的信息，而不是最大化实验数量。

## 补充练习

### 练习 8：字段缺失

线上关键字段缺失率突然上升，重新训练是否是第一动作？

答案：不是。先定位数据源、语义和回退，避免用新模型适应临时故障。

### 练习 9：定向抽样

只分析高成本错误，能否估计全部错误类型比例？

答案：不能，抽样分布被成本条件改变。

### 练习 10：多改动

一次实验同时改五项并提升，为什么不利于下一步？

答案：无法知道哪些项有效、是否存在交互，也难以复现最小改进。
